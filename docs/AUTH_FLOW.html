Authentication Flow

Sign-In Process

User submits credentials to /api/auth/sign-in
POST /api/auth/sign-in
{ "email": "admin@example.com", "password": "admin123" }
Elysia route handler forwards to BetterAuth native endpoint /sign-in/email
url.pathname = '/api/auth/sign-in/email'
return auth.handler(newRequest)
BetterAuth validates credentials against database
bcrypt.compare(password, hash)
Query user from PostgreSQL
Session created and cookie set
Set-Cookie: better-auth.session_token=xxx
Response: { "token": "xxx", "user": {...} }
Token returned to frontend for storage
200 OK
{ "redirect": false, "token": "yZ298ub6...", "user": {...} }

Session Validation Flow

Cookie-Based Auth (Browser)

Request with cookie sent automatically by browser
Cookie: better-auth.session_token=xxx
Middleware validates via requireAuth(headers)
auth.api.getSession({ headers })
BetterAuth checks session in database
SELECT * FROM session WHERE token = xxx
User data returned if session valid
200 OK
{ user: {...} }
Access granted to protected route

Bearer Token Auth (API/Mobile)

Request with Bearer token in Authorization header
Authorization: Bearer yZ298ub6...
Middleware extracts token and converts to cookie format
cookie: better-auth.session_token=token
BetterAuth validates session
auth.api.getSession({ headers: { cookie } })
User data returned if token valid
200 OK
{ user: {...} }
Access granted to protected route

RBAC Authorization Flow

After auth success, user ID is available
const { user } = await requireAuth(headers)
Workspace access check via requireWorkspaceAccess()
const { role, workspace } = await requireWorkspaceAccess(userId, workspaceId)
Role determination:
  • Owner - Full access (workspace.ownerId === userId)
  • Admin - Manage settings, invite members
  • Staff - Limited operations
  • Member - Basic read access
Permission check based on role
if (role === 'owner' || role === 'admin') { allow() }
Access granted/denied with appropriate status code
200 OK or 403 Forbidden

API Endpoints

Endpoint Method Description Auth Required
/api/auth/sign-in POST Authenticate user, return session token No
/api/auth/sign-up POST Create new user account No
/api/auth/sign-out POST End user session Yes
/api/auth/session GET Get current user session Yes

Error Handling

Status Code Error Code Description
401 UNAUTHORIZED Invalid or expired session, missing credentials
403 FORBIDDEN Insufficient permissions for workspace access
400 VALIDATION_ERROR Missing or invalid request parameters
500 INTERNAL_ERROR Server-side error during processing
